# 動態立繪：Inochi2D（規劃 2026-09-29，更新 2026-09-30）

> towerD 時期的決定和研究紀錄，保留當時的說法（例如立繪放在 `Assets`）。現在的流程以 [22b_Live2D_Flow.md](22b_Live2D_Flow.md) 為準。

目標：所有英雄的所有造型（含初始造型）都有「會動的立繪」和「會動的情境圖」，可以互動（點角色換表情、說話時嘴巴動），電腦和手機都能跑。

## 決定

| 環節 | 用什麼 |
|---|---|
| 拆圖層 | **See Through**（`Tools/art/see_through.py`）：一張立繪拆成約 22 層，被遮住的地方會補畫；拆不準時退回 `Tools/art/live_layers.py`（骨架＋SAM2） |
| 表情、嘴型差分、情境圖分層 | `Tools/art/live_layers.py` |
| 攻擊等大動作 | **關鍵姿勢立繪**（`Tools/art/key_poses.py`）：骨架圖＋ControlNet＋角色 LoRA，每個動作 2～3 張，各自拆層、綁定，遊戲裡交叉淡入 |
| 綁定 | 自動綁定 `Tools/art/inx_rig.py`，產生 Inochi2D `.inx`；需要時再進 Inochi Creator 精修。檢查：`rig_check.py`（靜止時跟原圖比）、`rig_stress.py`（轉關節找破洞和殘影） |
| 遊戲裡播放 | 自己用 GDScript 寫的 Inochi2D 播放器（`InochiPuppet`、`LivePortrait`），電腦和手機都能跑 |

程式的呼叫流程與每個函式的說明：[Code/README.md](../Code/README.md)。

## 2026-09-30 的查證與試作

**See Through**（shitagaki-lab/see-through，SIGGRAPH 2026；程式 Apache 2.0、模型 openrail++，可以商用；ComfyUI 節點 jtydhr88/ComfyUI-See-through）：
- 拆出前髮、後髮、臉、眼白、虹膜、睫毛、眉毛、嘴、鼻、耳、脖子、上衣、下著、左右手臂（連手套）、腿、手持物品，被遮住的地方都補畫。
- 放回原圖畫布後，除了「原圖看得到的地方用原圖的顏色」之外再補一層「其他」（模型漏掉的髮帶），疊回去跟原圖的平均差異約 1/255。
- 每張約 8 分鐘（16 GB 顯示卡）。
- 弱點：手持物品被遮住的部分會補成粗條（已限制在看得到的輪廓附近）；人物在畫面裡太小時五官會放錯位置（已改成先裁到人物再拆）；兩條腿是同一層。
- 有了分開的眼白、虹膜、睫毛，綁定可以做真的眨眼（眼皮蓋下），不用疊閉眼貼圖。

**Gemini 提到的其他工具**：LivePortrait（人臉偵測模型不能商用、只輸出影片）、THA3／THA4（THA4 不能商用；執行要大顯示卡）、Layer-Divider（比我們原本的做法還陽春）、NanoLive2D（沒有授權、要付費服務）都不採用。自動綁定方面已經有 Inkinesis（能輸出 Inochi2D，但部分元件是 GPL 授權，只參考做法）。

**Wan 2.2 動畫**：輕微的動態（風吹、頭髮、眨眼）效果好；拉弓放箭這種大動作在一秒後就崩壞（光線雜訊、畫面變暗、箭射不出去），不用在攻擊動作。

**關鍵姿勢試作**：艾莉西亞拉弓（待機、舉弓、拉滿、放箭，種子 64），角色 LoRA 讓臉和服裝一致，已經綁好並做成技能動畫預覽（`art_work/live/preview/alicia_bow_skill.gif`）。同一組姿勢要對齊軀幹長度和腳底位置（不要用臉的大小，側臉會量小）。

## 時限規則

有風險的研究先訂預計時間，最多兩倍（研究類最多 6 小時，3 小時後可以隨時切換替代方案），下載模型不計時。全身 Live 2D 做不起來時的替代方案：**臉部 Live 2D（眨眼、嘴型、表情、頭髮）一定保留**，全身動作改用 AI 動畫或關鍵姿勢交叉淡入。

### 2026-10-01 學到的事

**畫圖**
- 圖上不畫特效（火焰、魔法陣、閃電、寒氣）：遊戲自己會畫，畫上去的會重疊，拆圖層時也會變成不會動的碎片。排除詞見 `key_poses.NO_FX`。
- 武器的樣子跟著角色 LoRA 走：LoRA 學到的是原設計（芙蕾雅的彎頭寶珠杖），提示詞要照它描述，不要另外指定。
- 單手把長武器舉過頭，模型每次都畫成倒拿；改成雙手在胸前握直立的武器。
- 候選一律出 8 張，挑圖看全尺寸加骨架疊圖，不看縮圖（縮圖看不出兩根法杖、三隻腳）。
- 去背會留下武器和身體圍起來的背景，`key_poses.clear_background` 用背景色清掉。

**審圖工具** `Tools/art/review_plate.py`：原圖、原圖疊骨架、拆層分色（五官、頭髮、四肢、帽子、飾品、上衣、裙子、襪子、鞋子、武器、其他物件），自動警告：
- 武器超過一塊
- 鞋子或手套超過兩隻
- 沒有臉
- 其他物件太多
- 前髮跟原圖不同
- 有東西比腳底低
- 圖層疊回去跟原圖不同

**拆圖層的補救**（`see_through.py`）
- 沒拆出臉就換種子重拆一次。
- 某層在看得到的地方畫的跟原圖不一樣（雪乃的長髮蓋住整件褲裙），那塊從該層拿掉。
- 「其他」太多時再切：先找武器（細長的，或碰到手、肩的長條），再找臉上方的帽子，臀部以下剩的歸裙子。
- 關節缺值用畫圖時的骨架補，臉的位置用拆出來的眼睛校正。

**圖層順序**：每一層只有在 `parts.json` 的順序下自己是最前面的地方，顏色才是原圖的顏色；被擋住的地方是模型補畫的。綁定時身體各層的前後一律照 `parts.json`，否則被擋住的補畫會露出來（蕾娜的腰帶就是這樣不見的）。

## 2026-10-01 停損：骨架動作研究暫停

**決定（使用者）**：Live 2D 停在「臉部動態＋關鍵姿勢交叉淡入」。骨架動作（A 字站姿拆成可轉的手臂、腿、腰、武器，影片補中間影格→骨架→關節角度）暫停；工作重心改成把穩定的生圖工具整理給開發用。

**已經能用的**：遊戲內 Inochi2D 播放器（呼吸、眨眼、視線、嘴型、關鍵姿勢交叉淡入）；四位英雄的技能關鍵姿勢共 17 組，已拆層、綁定、通過 `rig_check`。

**骨架動作做到哪裡**（留在分支 `art-3` 與 `live2d-motion`，要重啟時從這裡接）：
- 只有芙蕾雅的 A 字站姿（`art_work/live/freya/pose_apose`）：手臂三段、完整法杖（`objects`＋`objects-back`）、左右腿三段、腰、`hidden`／`hidden-pelvis` 補畫層、所有轉軸。
- 預備→出招→預備的兩段影片（`art_work/motion/freya/`，Wan 2.1 Fun InP）與每格骨架；live2d 已能播出前傾、重心移動、抬腿、揮杖。
- 未解決：右腿後面（開衩處的裙子內側）補畫未驗證；肩膀、腰的補畫有抹痕（打算換 LaMa）；影片中被擋住的左手常讀錯；沒有腳尖資料（要換全身 133 點骨架）。

**停損的原因**：
- 芙蕾雅一組迭代約 8 版、4～5 小時，每版都有新問題。
- 其他三位英雄各估 4～6 小時；每位 11 套服裝還要再乘上去。
- 根本問題：AI 每次畫的不一致，拆層模型會補錯，會動的部位越多要補的地方越多。
- 戰場用的是 Q 版小圖，Live 2D 只出現在英雄畫面，效益有限。

**工具**（還能用在別處）：`rig_parts.py`（分零件）、`motion_clips.py`（兩張圖之間補影格＋每格骨架）、`multiview.py`（MV-Adapter 畫其他角度；角色 LoRA 要 ≤0.3，武器單獨跑）、`review_plate.py`（審圖）。
