# Live 2D 的製作流程（美術工作階段整理，2026-09-30；搬到 live2d-pipeline 後更新，2026-10-02）

這份整理的是美術工作階段做 Live 2D 的**整條流程**：每一步用哪支工具、輸入什麼、產出什麼、放在哪裡，以及踩過的坑。決定和來龍去脈見 [22_Live2D_Inochi2D.md](22_Live2D_Inochi2D.md)；程式說明見 [../Code/README.md](../Code/README.md)。

所有工具在 `Tools/art/`；拆層、找骨架、補畫、AI 重畫要本機的 ComfyUI（`http://127.0.0.1:8188`），分包、綁定、驗證不用。工作資料夾、立繪資料夾、ComfyUI、Godot 的位置都在 `live2d.toml`（環境變數可改）；工作資料夾目前是 `C:\Users\kwkev\Tool\art_work`，所有產出都放在這裡，不進版本庫。

## 甲、一張立繪的流程（穩定流程）

```
0 使用者選定立繪 ─→ 找骨架 [L1] ─→ 1 拆圖層 [L2] ─→ 1b 切零件、補完整 [L3]
  ─→ 2 分成六包：部件檢查 [L4]、組裝檢查 [L6]
       └ 有問題的物件 → 物件迴圈：輪廓 [L5a] → 上色或重畫的候選 [L5b] → 換上後再看 [L5c] → 回到 2
  ─→ 3 嘴型差分 [L7] ─→ 4 自動綁定 ─→ 5 跟原圖比、動態截圖 [L8]
  ─→ 6 人物的標準動作驗證（不含武器、物件）[L9]（分段手腳另跑壓力測試 [L12]）
  ─→ 7 武器與物件獨立驗證 [L10] ─→ 8 整合驗證（6、7 都通過才能做）[L11] ─→ 交付 [L14] ─→ 完成
```

`[L…]` 是 LLM 檢查點（見下一節）：每一步做完，LLM 先看過、通過了才往下走。

甲的固定流程到第 8 步整合驗證完成為止。人物本身、武器和物件各自先通過驗證，才能整合。

**物件要看得出來是物件**（使用者 2026-10-02，最重要的前提）：每個物件單獨拿出來看，要一眼認得出它是什麼：一隻手、一頂帽子、一束頭髮、一把杖。看不出來是什麼的（一塊說不出是什麼的色塊、手和前臂混成一團、上衣碎片被叫成上臂），不管其他條件多好都不算通過。完整、乾淨、符合名字都建立在這個前提上。

**驗證的優先順序**：① 物件完整度（每個部件完整、被遮住的也補好）→ ② 區塊組裝效果（每一包組起來的樣子）→ ③ 整體組裝效果 → ④ 動作。**原立繪只是素材，跟它逐點對齊不是目標**：為了對回原圖去補細節，反而會傷害拆層和部件的完整，所以跟原圖的比對只當參考數字，不當通過標準。

**每次都逐個物件檢查**（使用者 2026-10-02）：驗收不能只看組裝圖和動作截圖，**每個物件的檢查圖（分包工具的 `parts_<n>.jpg`，一包一張、每個物件單獨一格）也是驗收的一部分**，而且先看。組起來時物件互相遮住，物件本身髒不髒、完不完整看不出來：芙蕾雅初始服 AI 版組起來「很像原圖」，逐個物件看才發現帽子、披風黏著頭髮碎片、髮尾裡有白洞、側髮切成碎塊、雜物層只剩垃圾。每個物件要看：完整（沒有缺塊、被擋住的也畫好）、乾淨（沒有別的東西的碎片、沒有殘影和白洞）、符合它的名字（帽子是一頂帽子、側髮是一束頭髮）。交給使用者的成果也先附物件檢查圖，再附組裝圖和動作。

**組起來像原圖不是優點**：拿「跟原圖並排很像」當成果，會讓人（和程式）往貼回原圖像素的方向修，把拆層原本的錯誤一起帶回來（2026-10-02 檢討：放置工具 `--merge` 把原圖看得到的像素貼回 AI 畫好的物件、綁定時切掉人物輪廓外的像素、分包工具每次印跟原圖的差異百分比，都在往這個方向拉）。

Live 2D 工作室（`Tools/live2d_studio/app.py`，`http://127.0.0.1:7861`）每一步都有按鈕，不用打指令；程式的呼叫流程見 [../Code/08_Studio.md](../Code/08_Studio.md)。

### LLM 檢查點

**整條流程每一步都由 LLM 先替使用者檢查**（使用者 2026-10-01）。工具做完一步，LLM 打開那一步的檢查圖逐格看，寫下結果；通過才做下一步，沒通過就照下表修，修完再看一次。目前的 LLM 就是操作這些工具的 Claude 對話（用讀圖的方式看檢查圖），之後可以換成自動呼叫（見本節最後）。

**每個檢查點的做法**

1. **看圖，不看數字下結論**：程式印的數字和紅字警告只是提示，結論要看圖。數字說通過、圖上有破綻，算沒通過；紅字警告看圖確認是誤報，可以通過，但要寫明為什麼。
2. **逐個物件看**：有一格一物件的檢查圖時，每一格都要看、都要有結論，不能只看整體。每一格第一個問題是「看得出來這是什麼嗎」，看不出來就直接不通過。
3. **不拿「像不像原圖」當標準**：看的是物件完整、乾淨、符合名字，組起來前後對，動起來沒破綻。跟原圖的比對圖只當參考。
4. **寫下結果**：每個檢查點在工作資料夾的 `llm_checks.md` 加一筆：時間（先看時鐘）、檢查點、看了哪些圖、結論（通過／沒通過）、每個問題（哪個物件、圖上哪裡、建議怎麼修）。
5. **重試有上限**：同一個問題修兩、三次還不行，停下來標給使用者，附上修改前後的圖。
6. **交給使用者時**：先附物件檢查圖，再附組裝圖，最後附動作；連同 `llm_checks.md` 裡沒解決的問題。

### 三層檢查與重做上限（2026-10-02 定案）

檢查由小到大分三層，每一層都是「做 → LLM 看 → 不通過就重做」，而且每一層都有上限，不會無限迴圈：

| 層 | 做什麼 | LLM 看什麼 | 不通過 | 上限 |
|---|---|---|---|---|
| 一、物件 | 物件迴圈（輪廓、修補或 AI 重畫、換上） | 這一個物件（L5a～L5c、L4 那一格） | 重做這個物件 | 每個物件 **10 次**（測試期間，使用者 2026-10-02；原本 3 次） |
| 二、一包組裝 | 一包裡的物件組起來 | 這一包的組裝圖、這一包的部件動作（見下） | 點名出問題的物件，只重做那幾個 | 這一包的物件重做**總數不超過物件數的 2 倍**（至少 6 次）；組裝檢查最多 **3 輪** |
| 三、整個人物 | 六包組起來、綁定、動作 | L6、L8、L9 | 點名出問題的包和物件 | 組裝檢查最多 **3 輪**；整張立繪的物件重做**總數 30 次** |

**物件的結論有三種**：通過；重做；**要再拆**。動法不一樣的東西就該是不同的物件：會自己擺的（側髮、髮尾、披風、寬袖、裙子分片）、穿過人物前後的（帽子、圍巾）要拆開。拆的工具：`object_fix --carve`、`--split-hair`、`--split-front`；一大塊沒分好時，可以把那一塊裁出來再拆一次層。拆出來的新物件各自重新走物件這一層。

**不會無限迴圈的四道保險**：

1. **次數上限**（上表）：到了就停，寫進 `llm_checks.md`，標給使用者看。
2. **每次重做都要換做法**：換種子、換修法（修補 → AI 重畫 → 鏡像）、換提示詞或描點。同一個問題用同一種做法失敗兩次，就不准再用那種做法。
3. **通過的物件凍結**：之後只有組裝檢查明確點名它才能重做，而且算進那一層的上限。
4. **時限規則**：一張立繪先估時間，超過兩倍就停下來。

**多角度參考圖**（MV-Adapter，`multiview.py`）：拆完圖層、L2 通過之後，**每張立繪跑一次**，所有物件共用（要吃滿顯示卡，先請其他工作騰出來）。用來補正面看不到的地方（後髮、帽子後半、側髮），武器另外跑。

**主骨架和次要骨架分開測**：次要骨架指頭髮、裙子、披風等的擺動和連動變形。綁定還是一次做完（`inx_rig.py` 依名字自動綁），但動作驗證分兩段：先關掉擺動測大動作（看關節對不對），再打開擺動測甩頭、跳躍（看擺動對不對）。出問題時才分得出是關節的錯還是擺動的錯。

**部件動作測試**：在「一包組裝」和「整體動作」之間，只畫那一包加上它底下的補畫層，把它的參數轉到極限（手臂三段加身體：轉肩、肘、腕；頭部那幾包：轉頭、點頭、歪頭；腿加裙子：轉髖、膝）。整體一起動時物件互相擋住，問題容易被蓋掉。`rig_stress.py` 已經做到每個關節轉到兩端，但畫的是整個人。

**動作用最大動作截圖來看**：LLM 讀圖時動圖只看得到第一格，所以不看動圖。每個動作記下每一格的參數值，挑出參數到最大、最小的那幾格加上靜止那一格，原尺寸裁出人物排成一張圖（一個動作一列），疊上破洞、殘影的標記。L9、L11 看這張圖。

還沒做好的工具：最大動作截圖、部件動作測試、標準動作的「關掉擺動」選項（見本節最後「之後要補的」）。

### 各檢查點的注意重點

從 [../LessonsLearned.md](../LessonsLearned.md) 整理：過去在這一步漏看、看錯過的地方。括號是出處（LessonsLearned 的節，或程式裡記下的事件）。所有檢查點共通的：先看物件再看組裝（原則 1）、不拿像不像原圖當標準（原則 2）、重做到上限就交給使用者（原則 8）、說時間前先看時鐘（二）。

下面的例子（某個角色、某個部位）只是說明過去怎麼出錯，**不是規則**：碰到不一樣的情況，照 LessonsLearned 寫的原因去判斷，不要照例子套。

**L1 骨架**
- 盔甲、寬袖底下的手腕常抓錯或抓不到，手肘、手腕可能跑到肩膀上（四）。
- 握點常抓錯：抓到放在箭筒上的那隻手，或劍柄上方（四）。
- 膝蓋、腳踝要有，不然切不出腿（四）。
- 脖子跑到臉的高度、臉被伸出去的袖子誤認（`see_through.fix_grip` 記下的事件）。
- 關節點偏了，後面零件會接不起來（手腕高了 50 像素，前臂碰不到手）（五）：在這一步就修掉，比切完再補便宜。

**L2 拆圖層**
- 漏掉臉、兩隻眼白合成一層或只有一隻、發明不存在的帽子或翅膀（三）。
- 拆出來的臉離骨架的臉太遠：胸前的圖案被當成第二顆頭（`inx_rig.st_usable`）。
- 披肩的長髮被丟進「其他」（三）；跟同色披風疊在一起時，髮尾被分給衣服（三）。
- 手放在東西上會黏成一塊（艾莉西亞的右手和箭筒），之後會跟著手飛（三）。
- 「其他」佔人物一大半時（芙蕾雅的寬帽、杖、裙襬），看程式有沒有把帽子、武器、裙子分對（`refine_leftover`）。
- 被擋住的部分是模型猜的、常猜錯（額頭灰、帽帶抄進臉、帽簷殘影、後髮灰白）（三）：這裡先記下，留給物件迴圈修。

**L3 切零件**
- 手臂被袖子切斷、垂布比手還低時，肘、腕的位置容易切錯（`rig_parts.cut_arm`）。
- 上臂不能有超過肩膀、伸到身體那一側的部分，不然轉肩膀時會掃過脖子（`rig_parts.cut_arm`）。
- 四肢零件不能省：上臂、前臂、手；大腿、小腿、腳掌連鞋（原則 7）。
- 武器：SAM2 會流進同色的深色裙襬；被裙子擋住的杖下半截要補到腳底；補畫的部分要連著武器，不連的碎塊轉動時會留在原地（`rig_parts.py`）。
- 握點：程式取「碰到武器最多的手」，會抓錯（四）。
- `hidden`（手臂底下補畫的身體）：貼著皮膚的地方 AI 會畫出手臂的殘影；手臂和身體之間的空隙不該被補成一條皮膚；頭髮後面常補成灰色糊塊（`rig_parts.py`、五）。
- 站在裙子開衩裡的腿，後面要補成裙子內側。

**L4 部件檢查**
- 每一格都要看，先問「看得出來這是什麼嗎」（原則 0），再看完整、乾淨、符合名字（原則 1）。艾莉西亞的右上臂只是一塊上衣的白布、右手裡混著前臂和箭筒，就是看不出是什麼的例子。常見的髒：帽子、披風黏著頭髮碎片；髮尾裡有白洞；側髮切成碎塊；「其他」只剩垃圾。
- 被擋住的也要畫完整；左右成對的少一邊要從另一邊補（原則 6）。左右一對的大小、顏色差太多（一隻黃靴、一隻深褐）。
- 穿過人物的東西（帽子、圍巾、腰帶、繞過身體的武器）要拆成前後兩層（原則 7）。
- 會擺動的衣物（寬袖、披風、裙擺、馬尾、呆毛）要單獨切出來，才會擺。
- 零件上的小碎點會跟著零件飛（五）。
- 輪廓被切斷沒有可靠的自動判斷，只能靠看。

**L5a 輪廓**
- 擋在前面的東西的邊線，不是這個零件的邊：曾經把裙子前片的邊當成小腿的邊接起來，整塊被塗黑（五）。接線前先跟另一邊比。
- 被線隔開但還連著的區塊（黏在手臂上的披風），程式分不出來，要看編號決定 `--drop`。
- 成對的四肢有三成以上落在另一邊外面，表示混進了別的東西的輪廓（`outline.py`）。
- 邊緣的頭髮殘邊不要留給 AI 上色（會擴散成一圈紅邊），直接 `--erase-rgb` 刪掉（五）。

**L5b 候選**
- 從灰底重畫，AI 常照著背景留灰；檢查補的地方有沒有灰塊（五）。
- 「取最近的顏色」會拉出條紋，大片單色要用 `--palette`（五）。
- 鏡像的零件只能沿骨頭拉長，看有沒有整隻變粗（五）。
- AI 重畫（Mage-Flow）：大約一半照做；會改姿勢角度（手臂被拉直、弓弧畫反）；偶爾把臉畫進頭髮、人還在；沒要求改的地方也會變；被物件圍住的白色去不掉（六）。
- AI 重畫擅長頭髮、披風、帽子、直的武器；不擅長四肢、彎的武器（六）：四肢的候選要看得更嚴。
- 畫風要跟立繪一致（同一個模型和角色微調）。
- 用多角度參考圖取色的（`--from-view`）：背面圖的身體常畫不好（芙蕾雅背後是一塊粉紅），只取被擋住的部分（七）。
- 杖頭浮在彎鉤裡的寶珠算同一件，不算斷。

**L5c 換上之後**
- AI 畫的物件對位：細長的東西（法杖、手臂）用整體重疊對位容易歪，要看握點、關節點有沒有對上（六）。
- 不要用 `--merge` 把立繪的像素貼回去（原則 2）。
- 用方框切出來的零件（胸）邊緣會有縫，改用 `--carve-copy`（五）。
- 整層被切空的要刪掉，不要留在順序裡。

**L6 組裝檢查**
- 前後一律照 `parts.json`：換了順序會露出補畫的猜測（蕾娜的腰帶就是這樣不見的）。
- 帽帶在瀏海前、帽簷在頭後（原則 7）；披風在髮尾後面、側髮在上衣前、手臂後（八）。
- 前髮蓋住了護目鏡、眼睛這類東西（`review_plate.py` 的「前髮與原圖不同」）。
- 最後一張跟原圖的比對數字只當參考（原則 2）。

**L7 嘴型**
- 嘴型用的繪圖模型要跟這張立繪原本的畫風一樣，不然只有嘴的畫風會變。
- 只有嘴巴變；還是同一個人。

**L8 靜態**
- 眨眼：眼白和虹膜壓扁、閉眼圖最後兩成淡入，看有沒有露出眼白殘影。
- 轉頭：前髮、後髮有前後深度；領口跟著滑。
- 縮圖看不出細微的問題（十一），有疑問看原尺寸。
- 跟原圖的比對圖只當參考（原則 2）。

**L9 人物的標準動作**
- 程式只能確認參數齊不齊；破綻要看畫面：東西跟著手飛（箭筒）、手腕有縫、碎片在飛（十一）。
- 站得窄的角色腿會交叉；長裙裡的腿不能踢出裙外（八）。
- 揮手時手臂要往外舉，不是往胸前收（參數方向左右一致，八）。
- 裙子、頭髮要慢半拍甩、會停下來；擺不動表示擺掛錯節點；擺兩倍快表示一格更新了兩次（八、九）。
- 手臂舉起來後露出的 `hidden` 有沒有灰色糊塊；胸的切口有沒有縫。
- 細微的動作（胸部彈動、領口）縮圖看不出來，要實際大小、實際速度看（十一）。

**L10 武器與物件**
- 武器要一整塊；浮在彎鉤裡的寶珠算同一件。
- 被手擋住的那段有沒有補起來，轉到背面時 `objects-back` 接不接得上。
- 箭筒、腰包這類不是武器的東西，不該黏在手上（三）。

**L11 整合**
- 握點抓錯時，武器會跟著錯的那隻手（四）。
- 揮手、跑步時武器有沒有穿過身體或甩到奇怪的角度。

**L12 壓力測試**
- 先排除誤報：手臂移開後露出人物外面的背景是正常的；小轉動時零件邊上的細條不算。
- 真的問題：手臂底下沒補畫（`hidden`）、關節裂縫、手指留在身體層、排在後面的武器被前面的層畫成立繪顏色（殘影）。
- 修不好的關節用 `--find-ranges` 縮小範圍，技能動作留在範圍內。

**L14 交付**

- 列出 `llm_checks.md` 裡沒解決的問題。

### 物件拆法（每個物件都走這個迴圈）

拆層和切零件都照同一個迴圈做，由小到大一層一層往上：**物件 → 部件（一包）→ 整體 → 動作**。每一層都先評價、補好，才往上一層。

**先輪廓、後顏色**（使用者 2026-10-01 定的做法）：物件的輪廓要先完整，再填顏色。形狀由輪廓線決定，輪廓外面的就是噪點，輪廓裡面沒顏色的就是要補的，判斷都變得明確。

1. **把物件拆出來**。
2. **抽出輪廓線條**：動漫畫風的輪廓是深色線。物件的邊上 2 像素內有深色線的是「畫出來的邊」；沒有的是「切開的邊」（被別的東西擋住，或拆層時切斷）。
3. **補齊線條，刪掉輪廓以外的噪點**：在每段切開的邊的兩端，順著原本輪廓的方向把線延伸下去。四肢延伸到骨架範圍的盡頭再接起來；武器把斷開的幾塊用一樣粗的線接起來；其他物件在兩條線交會處接起來，不交會就直接橫著接。接好後，最大的那一個封閉形狀就是物件（包在它輪廓裡的小塊，像彎鉤裡的寶珠，也算）；輪廓外面的一律刪掉。被線隔開但還連在一起的區塊（黏在手臂上的披風），程式分不出是不是物件的一部分，檢查圖上會編號，人看過再指定刪掉。
4. **跟抽出的物件比對，補上缺少的顏色與細節**：只在輪廓裡面、原本沒顏色的地方重畫；補好的輪廓線當線稿，讓 AI 照著線上色（萬用控制模型的線稿模式），不會畫出界。
5. **檢查物件完整度**：一整塊（包在輪廓裡的浮動小塊另計）、輪廓外面沒有東西、輪廓裡面沒顏色的不超過 2%。再看一眼是否符合描述（補完的手臂像一條手臂、左右一對長得像一對、畫風跟原圖一致），不符合回到第 3 或第 4 步。

- 工具：`outline.py <hero> <series> <圖層> [--src orig] [--drop 編號] [--erase 框]`（第 1～3 步，不用顯示卡），產出 `st/outline/`：線稿、封閉形狀、要上色的範圍、檢查圖（綠＝畫出來的邊、紅＝切開的邊、黃＝刪掉的、藍＝補上的線、洋紅＝要上色的）。`object_fix.py <hero> <series> <圖層> --outline`（第 4 步，要 ComfyUI）。`outline.py ... --check [--file 候選圖]`（第 5 步）。
- **LLM 檢查**：抽完輪廓 **L5a**、出了候選 **L5b**、換上之後 **L5c**。
- **誰來判斷**：由 Claude 自動操作（使用者 2026-10-01 同意）。Claude 看每個零件的輪廓檢查圖，自己標出不屬於它的區塊、描出缺的輪廓，程式做其餘的；最後把修改前後的對照圖給使用者看。同一個零件試兩、三次還不對，才標出來請使用者動手。標記存在 `st/outline/marks.json`，重跑時自動套用：`--erase-poly`（多邊形內刪掉）、`--erase-rgb`（邊上 6 像素內某個顏色刪掉，例如鏡像帶過來的紅髮邊）、`--line`（手描一段輪廓）、`--drop`（刪掉編號區塊）、`--erase`（框）。
- **線從原圖抽**：`outline.py <hero> <series> lineart` 用線稿抽取器（ComfyUI 的一般線稿抽取，比動漫專用的線乾淨）把整張立繪的線抽成 `st/lineart.png`，之後判斷「畫出來的邊」和「被線隔開的區塊」都用它，再加上零件本身的深色像素。只算零件邊緣往內 1 像素以內的線：被擋住的地方，原圖上的線是前面那個東西的。
- **延伸的規則**：兩端延伸一樣長（取短的那邊），避免一長一短變成尖角；兩條線往內收（延伸後的距離比切口窄四成以上）就直接橫著接。
- **被擋住的地方是猜的**：拆層模型只在一個圖層是最前面的地方給原圖顏色，被擋住的地方是它猜的，常常猜錯（芙蕾雅的臉：被瀏海和帽子擋住的額頭填成灰色，還把帽帶的黑、紅抄進臉裡；帽子：頭後面那段帽簷沒補，留下灰色殘影）。`object_fix --flat`：輪廓裡被前面圖層蓋住的、跟原圖對不上的、別的圖層也在這裡顯示原圖顏色的（屬於那一層）、離自己顏色很遠的一大塊或有顏色的碎點（別的東西，另存成 `fix/<圖層>_moved.png` 還給它該屬的圖層），全部改成看得到的部分的中位數顏色；被瀏海蓋住的額頭本來就是平塗的皮膚色。`--flat --nearest`：只補輪廓裡空的地方，每個像素取最近的看得到的顏色（灰白殘影不當來源）。`outline.py --no-grow`：形狀已經完整（臉）只補洞，不延伸。
- 芙蕾雅的臉照這樣修好；臉裡的帽帶還給帽子。帽子的帽簷下緣用左右兩邊的弧線補齊了，但被臉擋住的那段帽簷前緣，AI 上色畫成頭髮，最近顏色填也拉出條紋，還沒換上。
- **穿過人物的物件拆成前後兩層**（使用者 2026-10-02 確認）：一個物件有一部分在人物前面、一部分繞到後面（帽子：帽冠、帽帶壓在額頭和瀏海上，帽簷繞到頭後面；圍巾、腰帶、披風、繞過身體的武器也是），只用一層一定有一邊疊錯。拆法：原圖上這個物件蓋在臉、瀏海上的部分（顯示原圖顏色的像素）另成「<名稱>-front」，排在前髮後面（最前面）；其餘留在原位（在臉後面）。兩層掛同一個節點、用同一個擺動，看起來還是同一個物件。工具：`object_fix.py <hero> <series> <圖層> --split-front`；綁定和分包認得 `headwear-front`。芙蕾雅的帽子拆完後，轉頭、點頭時帽帶壓在瀏海上、帽簷在頭後面。
- **雜物層裡的頭髮**：拆層模型只認得前髮、後髮，披在肩上垂到腰的長髮會被丟進雜物層 `leftover`；分包以前只照位置切（脖子以下歸「其他」），長髮就跑到第 6 包、綁在腰上不跟頭走。`object_fix.py <hero> <series> leftover --sort-hair`：雜物層每一塊獨立的東西，大多是頭髮顏色（前髮的中位數顏色）、或有三成是而且碰到頭髮層的，移到新圖層 `side_hair`（排在雜物層原本的位置），分到頭髮包；綁定掛在頭上、在上衣前面、手臂後面，有自己的擺動（`SWING["lock"]`）。芙蕾雅的雜物層 93% 移成側髮，甩頭時長髮跟著頭走。
- **多角度參考圖**：`Tools/art/multiview.py`（MV-Adapter，美術工具箱做的、交接時給了）從一張正面立繪生成正面、右側、背面、左側四張（768 像素，用我們的模型加角色微調，強度 ≤ 0.3）。用途是被擋住部分的參考（後髮、帽子後半、側面的耳朵和側髮），看得到的部分還是用原圖。
- **用多角度圖補被擋住的部分**：`object_fix --flat --from-view <角度圖>[:flip]`，把多角度圖照 `multiview.py` 的裁切和縮放放回立繪上，輪廓裡猜錯、被擋住、空的像素取角度圖同一處的顏色（要是這個物件的顏色，或旁邊有這個顏色的細深色線＝髮絲；粗的深色塊是帽子底面、衣服，不取），取不到的用最近看得到的顏色（不取深色輪廓，避免黑色往內抹）。從正面看身體後面的後髮＝背面圖左右翻轉。芙蕾雅的後髮用 A 字站姿（扣掉法杖、補畫層）重跑的背面圖補成紅色、帶髮絲線；手舉起來時後面露出的是紅髮，不再是灰白色。中間還有幾個束腹綁帶的痕跡（束腹和頭髮同一個紅，分不開），永遠在身體後面。
- **衣服裡的頭髮**：頭髮披在同色的披風上時，拆層模型會把髮尾分給衣服。`object_fix --move-hair [--ycut 列] [--palette 顏色] [--keep-holes]`：用原圖線稿把紅色切成一塊一塊，15 像素內有頭髮灰藍陰影、中心在 `--ycut` 以上、又不是整片大塊（披風本身）的，移到側髮；衣服上的洞用最近的顏色補（只取 `--palette` 的顏色，披風本來就延續到頭髮後面），或像身體底下補畫一樣留空（`--keep-holes`，順便清掉 80 像素以下的碎點）。`--drop-specks N`：清掉一個圖層裡小於 N 像素的碎點。芙蕾雅：下著移出 16478 像素髮尾、身體底下補畫移出 20206 像素（前一晚補成紅髮的那些），甩頭時髮尾跟著頭走，後面露出的是披風的紅。
- 成對的四肢會拿另一邊翻過來比：這邊的形狀有三成以上落在另一邊外面，就是混進了別的東西的輪廓（芙蕾雅的右上臂、右前臂混進披風），建議改用另一邊鏡像（`object_fix --mirror`）或指定刪掉。手不比（握拳和張開本來就不一樣）。
- 芙蕾雅試跑（原始零件）：法杖的輪廓 97% 是畫出來的，照線稿上色後連寶珠都長出一根柄接到杖頭，檢查「一整塊、全部上色」通過（原本是兩塊、3.2% 沒顏色）；左大腿往膝蓋延伸的一段照輪廓補成皮膚；右上臂、右前臂被標出混進披風。

**組裝成部件（一包）之後**，一樣評價圖片是否正確、有沒有重大缺漏；再組成整體評價；最後用標準動作評價。任何一層發現問題，都回到出問題的那個物件，照 1～3 重做。

做法上的細節：

- **由後往前補**：先補最後面的物件（身體、腿），再補前面的（手臂、武器、頭髮）。前面的物件擋住後面的，後面的先補好，前面的才有東西可以蓋。
- **單獨補**：補一個物件時，把它單獨放在空白的畫布上補（只給它自己的輪廓和被擋住的範圍），AI 才不會順手把旁邊的東西畫進來。用跟原圖同一個模型和角色專屬微調，畫風才會一致。
- **缺的範圍從骨架推**：手臂應該從肩膀一路到手腕、手，腿到腳踝、腳掌；原圖沒畫到的就是要補的範圍。左右成對的缺一邊，用另一邊鏡像當底稿（見上面「被遮住的也要畫完整」）。
- **「符合描述」怎麼判斷**：部件檢查圖給人看；另外可以用圖片標籤模型（例如 WD14）替每個物件打標籤，對不上名稱的（標成手卻被認成腰包）先標出來。
- **重做有上限**：同一個物件補兩、三次還不行，就停下來標給使用者看，不要一直重做（時限規則）。
- **原圖只是素材**：評價的是物件本身完不完整、組起來對不對，不是跟原圖逐點一樣。

**工具：單獨補一個物件**　`object_fix.py <hero> <series> <圖層> [--dry] [--seeds 1,2,3] [--erase x0,y0,x1,y1;...] [--apply <seed>]`（要 ComfyUI；`--dry` 不用）。工作室：「資料夾 → 單獨補一個物件」。

1. 清掉離主體太遠的碎點（太大的塊留著，例如法杖上的寶珠），`--erase` 手動框掉截錯的區塊。
2. 算出要補的範圍（洋紅色）：四肢從骨架推（上臂從肩膀到手肘、手從手腕往外），武器把斷開的幾塊用跟杖身一樣粗的線接起來，其他圖層補被前面圖層擋住、靠近自己邊緣的地方。
3. 單獨放在灰色畫布上放大，只重畫要補的範圍，用立繪的模型加角色專屬微調；畫出來還是灰色背景的地方不算。
4. 產出 `st/fix/<圖層>_<seed>.png`（候選）和 `st/fix/<圖層>.jpg`（原本、要補的、每張候選並排），人看過挑一張 `--apply`，原本的存在 `st/_orig/`。

芙蕾雅 A 字站姿第一次用（2026-10-01）：法杖斷成三塊（杖頭彎鉤、杖身、寶珠）。彎鉤和杖身之間補上了；寶珠在原圖上本來就是浮在彎鉤裡，AI 不會替它畫柄，所以物件驗證改成「在主體輪廓（凸包）裡的小塊算同一件，另外列為浮動部件」。

另外三種用法（同一天、芙蕾雅的右手臂，被披風和法杖擋得最多）：

- `--mirror`：成對的一邊拆壞了（右上臂混進披風、右前臂幾乎都是披風），拿另一邊的零件左右翻轉、依骨架轉到這邊的骨頭上當底稿，AI 再輕輕修一次（強度 0.4）。
- `--grow hull`：只補自己幾塊之間的空隙（握著法杖的右手被杖身切成兩半）。
- `--desc`：預設的描述不合時換掉（握拳的手寫成 "clenched fist, hand gripping"）。
- `--grow grey`（加 `--grey-sat`、`--only` 框範圍）：圖層裡面灰白的糊塊重畫（以前補畫時照著灰底留下來的）。芙蕾雅的「身體底下補畫」在手臂後面有這種糊塊，手舉起來就露出來；只框腰以上，免得把白皙的大腿也當成糊塊。

補畫前先把要補的地方填上物件最近的顏色、強度 0.8；直接從灰底重畫（強度 1.0）時 AI 常常照著背景留灰，補不出東西。

### 骨架與連動

骨架只有會運動的大關節：頭（轉、點、歪）、腰、肩／肘／腕、髖／膝／踝、武器的握點。其他東西不另外做關節，照下面三種方式跟著動（一個物件可以同時用幾種）：

1. **掛在節點上（跟著走）**：指定物件掛在哪個關節底下，關節一動它就跟著動。最簡單，現在的綁定就做得到。
2. **擺動骨架（有物理）**：垂下來、會晃的東西各自加一根擺（跟頭髮同一套物理），身體一動它就慢半拍甩一下再回穩。
3. **連動變形**：關節附近的衣服不硬轉，照離關節的遠近跟著關節角度一起拉、擠（越靠近手臂的點跟得越多）。Inochi2D 的「參數帶動網格變形」做得到，最費工，最後做。

要擺動或變形的衣物，拆層時要切成單獨的物件（寬袖的垂布、裙擺分片、披風），一樣走上面的物件拆法。綁定照下表自動做，不用每張立繪手調；標準動作驗證多看一項「連動對不對」（揮手時袖子跟著、跑步時裙擺晃）。

### 2. 分成六包：部件檢查、組裝檢查

See Through 一次產生全部的層（不能分六次跑），拆完照固定順序分成六包，每包一個資料夾，依序檢查。某一包有問題時只重做那一包的補救（例如用 SAM2 重找武器或帽子）。

「必有」＝每張立繪都該有，沒有就是拆壞了（分包時會警告）；「可能」＝看造型和姿勢，沒有是正常的。括號裡是檔案名稱（`st/part_<名稱>.png`）。

**被遮住的也要畫完整**：每個部件都要是完整的，被頭髮、手、衣服或角度擋住的部分也要補畫出來，否則轉頭、甩頭、揮手這些大動作時會露出破綻。左右成對的部件（眼白、虹膜、睫毛、眉毛、耳朵、手臂）兩隻都要有：側臉或被擋住只拆出一隻時，另一隻要補畫（分包時會警告「只有一隻」）。原圖上完全沒有的，用 AI 照另一側的樣子補出來：以臉（或身體）的中線把看得到的那隻鏡像過去當底稿，再用 AI 局部重繪修成這一側的角度和光影，一樣要跟原圖畫風一致。整個部件都沒拆出來的（例如眉毛整個被帽簷擋住），也用 AI 照角色的樣子畫在被擋住的位置。

**1 臉部**（跟著頭轉）

| 圖層 | | 說明 |
|---|---|---|
| 臉 `face` | 必有 | 臉的皮膚 |
| 左右眼白 `eyewhite-l/r` | 必有 | 兩隻都要有；側臉或被瀏海擋住時，看不到的那隻也要補畫 |
| 虹膜 `irides-l/r` | 必有 | 兩隻都要有；側臉時拆層模型會把兩眼合成一層 `irides`，要分開並補畫看不到的那隻 |
| 睫毛 `eyelash-l/r` | 必有 | 兩隻都要有；眨眼時往下蓋 |
| 眉毛 `eyebrow-l/r` | 必有 | 兩隻都要有；被瀏海或帽簷擋住的部分也要補畫完整 |

| 耳朵 `ears-l/r` | 可能 | 造型有露耳時兩隻都要有；被頭髮蓋住的部分也要補畫 |
| 帽子 `headwear` | 可能 | |

| 領口 | 看一下 | 在上衣裡，這包一起看，綁定時留在身體上 |

**2 頭髮**（各自有擺動的物理）

| 圖層 | | 說明 |
|---|---|---|
| 瀏海 | 必有 | 額頭前面那片 |
| 後髮 | 必有 | 頭後面的主體 |
| 左右側髮 | 可能 | 臉兩旁垂下的髮束（鬢角、長側髮） |

拆層模型只分前髮 `front_hair`、後髮 `back_hair` 兩層，上表的細分要在拆完後再切（瀏海和側髮從前髮切，馬尾、髮尾、呆毛從後髮切）。

**3 軀幹與衣物**（身體跟穿在身上的衣服一起切；胸會呼吸、有乳搖，腰可以彎）

| 圖層 | | 說明 |
|---|---|---|
| 胸 `chest` | 必有 | 胸口到胸下緣，連著上衣這一段；呼吸時起伏，乳搖的物理掛在這裡 |
| 腹 `abdomen` | 必有 | 胸下緣到腰，連著上衣或腰封這一段；腰彎的時候跟著彎 |
| 小腹 `belly` | 可能 | 腰到下著上緣，露出小腹或衣服在這裡分段的造型才有 |
| 下著 `bottomwear` | 可能 | 裙子、短褲、褲裙，掛在骨盆上；連身裙時沒有 |
| 身體底下補畫 `hidden`、裙子往上延伸 `hidden-pelvis` | 可能 | 手臂、腿、武器移開後，或上身彎下時露出來的身體和衣服（切零件時補畫） |

拆層的上衣 `topwear` 是原料（含領口、披風、外套；連身裙也在這層），切成胸、腹、小腹後就不直接用了。披風、外套下擺這種會自己擺動的，之後可以再切出來加物理。

**乳搖**：胸 `chest` 的網格下半部掛一個彈簧擺的物理，身體上下移動（走、跑、跳、受擊）時跟著晃，停下後回穩；幅度保持輕微自然，跟頭髮物理同一套做法。胸是完整的一塊，不另外挖洞，所以晃的時候不會露出縫。角色一律是成年人，服裝照原圖，不做裸露。

| 左右大腿 `thigh-l/r`、小腿 `shin-l/r` | 必有 | 從拆層的腿 `legwear`（連襪子，兩條腿同一層）切開左右再切段，髖、膝可以轉；被長裙或另一條腿擋住的部分也要補畫 |
| 左右腳掌 `foot-l/r`（腳踝以下，連鞋子） | 必有 | 光腳或穿鞋都要：從腿 `legwear` 和鞋子 `footwear` 切出腳踝以下，鞋子跟著腳掌走；腳踝可以轉（踮腳、跳躍落地、走路） |

拆層的 `handwear-l/r`、`legwear`、`footwear` 是原料，切好零件後就不直接用了。

| 動作 | 看什麼 |
|---|---|
| 走路 | 上下起伏、左右晃、雙手前後擺、頭輕輕點 |

| 眨眼與表情 | 眨眼、眼睛左右看、挑眉、說話 |

| 甩頭 | 快速轉頭兩秒再停，看頭髮甩動和回穩 |

## 乙、骨架動作流程（已停損，留作重啟用）

使用者提出的流程：**生成立繪 → 拆層、標記物件 → 判斷每個物件是否完整 → 補齊不完整的物件 → 重新組裝並檢查 → 動作測試**。試作只做到芙蕾雅的 A 字站姿（`art_work/live/freya/pose_apose`）。

```
A 字站姿立繪 ─→ See Through 拆層 ─→ 分零件（rig_parts）─→ 補被擋住的地方 ─→ 轉關節壓力測試（rig_stress）
                                                   ↑                                   │
                                     其他角度（multiview）                              ↓
                                    兩張關鍵姿勢 ─→ 影片補中間影格（motion_clips）─→ 每格骨架 ─→ 綁定播放
```

1. **A 字站姿立繪**：`key_poses.py` 的 `apose` 姿勢（手離開身體，武器拿直）。
2. **拆層**：同甲-1。
3. **分零件**：`rig_parts.py <hero> <series> [--weapon x,y;... --not x,y;...]`
   - 武器：SAM2 沿武器取點切出來，從原本所在的層拿走；被手擋住的部分用截面延伸補齊（不靠 AI 猜）；手後面那段放 `objects-back`。
   - 手臂：從肩膀沿手臂走的距離切成上臂／前臂／手（手肘約一半、手腕約 0.8），每段在關節處多留圓頭，轉動時不會裂開。
   - 腿：大腿／小腿／腳，加上髖、膝、踝、腰的轉軸；上衣往下蓋的部分跟著走；`hidden-pelvis` 補骨盆。
   - 產出寫回 `st/`：`part_upperarm-l.png` 等，`parts.json` 多了 `pivots`（肩、肘、腕、握點、武器尖端）。
4. **補被擋住的地方**：手臂、武器移開後露出的身體用 AI 補畫在 `hidden` 層；接縫用 Telea 修補；腿之間的小洞也補。
   - 問題：肩膀、腰的補畫有抹痕，打算換 LaMa（`big-lama.pt` 放在 ComfyUI 的 `models/inpaint`）；右腿後面（開衩處裙子內側）沒驗證。
5. **轉關節壓力測試**：`rig_stress.py freya/pose_apose`：每個關節轉到兩端，找破洞（背景透出來，洋紅色）和殘影（移走的零件還留在原處，青色），產出 `art_work/live/check/<name>_stress.jpg`。
6. **其他角度（補正面看不到的資訊）**：`multiview.py <plate.png> <out_dir> --lora freya`，用 MV-Adapter 畫 4 個角度。
   - 在獨立環境跑：`C:\Users\kwkev\Tool\mvadapter-env`（借 ComfyUI 的 torch），程式在 `C:\Users\kwkev\Tool\MV-Adapter`，設定檔在 `C:\Users\kwkev\Tool\sdxl-config`，要設 `HF_HUB_OFFLINE=1`。
   - 角色 LoRA 要 ≤0.3（`MV_LORA_SCALE`，0.8 會每個角度都變正面）；只能 4 個角度（6 個會超過 16 GB，掉到共用記憶體變超慢）；不要開 CPU 卸載（會壞掉）。
   - 使用者建議：**用物件去跑，不要用整個角色**（武器單獨跑）。
7. **影片補中間影格**：`motion_clips.py <hero> <from_pose> <to_pose> [--frames 25] [--seed 3]`
   - 模型：Wan 2.1 Fun InP 1.3B（給頭尾兩張，補中間；Apache 2.0）。影片只拿來讀骨架，畫面壞掉沒關係。
   - 每格讀骨架（含膝、踝），左右不會對調：頭尾兩端固定，上半身、下半身分開用動態規劃對齊；跳動太大的點丟掉再補。
   - 產出：`art_work/motion/<hero>/<from>_to_<to>/frame_*.png`、`preview.gif`、`<from>_to_<to>.json`（每格關節座標）。`--skeleton-only` 只重算骨架。
   - live2d 那邊已能把這些骨架轉成關節角度播出來（前傾、重心移動、抬腿、揮杖）。
8. **還沒解決**：影片中被擋住的左手常讀錯；沒有腳尖資料（要換 133 點的全身骨架）。

**停損原因**：芙蕾雅一組迭代約 8 版、4～5 小時，每版都有新問題；其他三位各估 4～6 小時，每位 11 套服裝還要再乘上去。根本問題是 AI 每次畫的不一致、拆層會補錯，會動的部位越多要補的越多；而且戰場用的是 Q 版小圖，Live 2D 只出現在英雄畫面。

## 技能關鍵姿勢與預覽（甲完成之後；位置等乙的流程定下來再調整）

### 技能關鍵姿勢

每位英雄的技能用 2～4 張關鍵姿勢交叉淡入，穿的是這張立繪的造型：

| 英雄 | 技能 | 關鍵姿勢（資料夾 `pose_<名稱>`） |
|---|---|---|
| 艾莉西亞 | 弓 | raise 舉弓 → draw 拉滿 → release 放箭 |
| 芙蕾雅 | 法杖，爆炎球 | raise 雙手握直立法杖聚力 → cast 法杖前伸 → recover 收勢 |
| 雪乃 | 摺扇，冰封 | open 展扇 → sweep 橫掃 → point 扇尖指向 |
| 蕾娜 | 大扳手，部署砲台 | windup 扳手舉過頭 → slam 砸地 → impact 扛肩 |

另外每位都有 `idle`（待機）、`ready`（預備）。

1. **候選**：`key_poses.py cand <hero> <action>`。每個姿勢在程式裡畫 OpenPose 骨架（`POSES`），接 xinsir openpose ControlNet ＋ 角色專屬微調（強度 1.0）＋ 她的服裝標籤，每個姿勢出 8 張，放在 `art_work/poses/<hero>/<action>/`。骨架統一**軀幹長度和腳底位置**（不要用臉的大小對齊，側臉會量小）。
2. **審圖、你挑**：`review_plate.py cand <hero> <action>` 產生候選的審圖表（警告同第 2 步）。挑哪一張由使用者決定。挑好後 `key_poses.py pick <hero> <action> <pose>=<seed> ...`：去背（`clear_background` 會清掉武器和身體圍起來的背景）並用局部重繪做閉眼圖，放進 `pose_<pose>/`。
3. **你的審核**：選用的姿勢走完第 1～2 步後，在美術工具箱「待審核」按「可以／不行」（不行要寫原因）。決定存在 `art_work/review_decisions.json`，鍵是 `pose:<hero>:<pose>`。**這個檔案是使用者的，不要刪、不要蓋掉。** 已交給綁定的姿勢記在 `art_work/delivered.json`。
4. **每張姿勢再走甲的 1～6**。

### 技能預覽

- `Tests/live/skill_preview.tscn`：待機 → 技能的各個姿勢 → 待機，交叉淡入加特效（射箭、火球、冰霜、砸地），存成 `art_work/live/preview/<hero>_<樣式>_skill.gif`。缺的姿勢用待機代替。

## 畫圖時學到的規則

- 圖上**不畫特效**（火焰、魔法陣、閃電、寒氣）：遊戲自己畫，畫上去會重疊，拆層時也會變成不會動的碎片。排除詞在 `key_poses.NO_FX`。
- 武器照角色 LoRA 學到的原設計描述（芙蕾雅是彎頭寶珠杖），不要另外指定。
- 單手把長武器舉過頭，模型每次都畫成倒拿；改成雙手在胸前握直立的武器。
- 候選一律 8 張，挑圖看全尺寸加骨架疊圖，不看縮圖（縮圖看不出兩根法杖、三隻腳）。
- 年齡只寫數字（二十多歲），負面提示詞保留 `child, loli`；可以性感，不能裸露。
