# 一張立繪的流程（主流程）

一位角色的一張立繪（主設計或一套造型），從使用者選定開始，一路做到它在遊戲裡會動。一次只做一張。流程由流程程式 `wf` 照 [`flows/plate.toml`](../../flows/plate.toml) 一步一步跑，每一步做完由 LLM（操作這些工具的 Claude 對話）看圖下結論，通過了才往下走。

這份是總覽；每一步的工具、要看什麼、修法、常見問題寫在各步驟的文件（下表的連結）。設計的來龍去脈在 [../Design/](../Design/)（22 系列、23 流程程式的設計），程式說明在 [../Code/](../Code/README.md)，通用心得在 [../LessonsLearned.md](../LessonsLearned.md)。

## 1. 目標和範圍

- **產出**：一個 Inochi2D 模型（`<角色>_<造型>_st.inx`），呼吸、眨眼、說話、轉頭、十個標準動作都不破。
- **目前只做人物**（使用者 2026-10-02）：帽子、髮飾算人物（頭髮包）；武器和手上拿的東西在分包後整層拿掉（原檔留著），物件驗證和人物物件整合先跳過（第 13 步）。
- **原則**（[LessonsLearned 一](../LessonsLearned.md)）：
  0. 物件要看得出來是物件：每個物件單獨看，一眼認得出是什麼；看不出來的，其他條件再好也不通過。
  1. 先看每個物件，再看一包組起來，再看整個人，最後看動作。
  2. 原立繪只是素材，組起來像原圖不是目標；物件只要正確、畫風接近。
  3. 被擋住的也要畫完整；左右成對的少一邊從另一邊補。
  4. 會分開動的就是不同物件（四肢分三段，會擺的髮束、裙片單獨切）。

## 3. 審查迴圈（每一步都一樣）

```
程式跑這一步的工具 → 出一份審查包 → LLM 看圖、寫結論 → 程式照結論執行修法 → 再出一份審查包 → … → 通過，下一步
```

- **審查包**：工作資料夾 `reviews/<檢查點>-<第幾次>/`，有這一步的圖、`request.json`（要判斷的項目、注意重點、這一步的修法選單、重做次數、被禁用的修法、工具的提示）。`wf review <角色>/<造型>` 印出來。
- **結論**：寫 `verdict.json`，用 `wf verdict` 交。每一項：
  - `verdict`：`pass`（通過）、`redo`（重做）、`split`（要再拆）；
  - `reason`：**要寫出看了審查包裡哪一張圖**、看到什麼；
  - `problem`（不通過時）：看不出是什麼、不完整、有碎片殘影白洞、位置大小不對、前後錯、畫風不對 六種之一；
  - `fix`：從這一步的選單挑；物件迴圈的 5b 通過時要寫 `pick`（挑哪一張）；
  - `confidence`：`high` 或 `low`（`low` 會停下來等使用者看）。
  格式不合，整份退回、什麼都不執行。
- **先看圖再寫結論，沒有例外**（2026-10-03 檢討：兩次先寫後看）。
- **手改**（選單裡的 `manual`）：選單沒有的修法，先自己改好檔，`what` 寫清楚改了什麼。每一次手改都記在 `run.json` 的 `manual`，交付時列成「要做成工具」的清單。同一種手改每一輪都出現，就該變成選單裡的修法或固定步驟（見各步驟文件的「常見問題」）。
- **紀錄**：每份結論也寫進工作資料夾的 `llm_checks.md`。

## 4. 使用者親自把關的地方

- 第 0 步選立繪、第 14 步交付：結論 `by` 要是 `user`，**要使用者親口確認**，不能拿使用者先前的同意代寫（2026-10-02）。
- 信心低的結論。
- 被重做上限擋住時：只有使用者能用 `wf unblock` 放行（`--more N` 多給幾次，寫原因）。

## 5. 重做上限和保險

| 層 | 上限 |
|---|---|
| 一個物件 | 10 次（測試期間；原本 3 次） |
| 一包的物件重做總數 | 物件數 × 2，至少 6 次；組裝檢查最多 3 輪 |
| 整張立繪 | 物件重做總數 30 次；組裝檢查（L6、L9、L11）最多 3 輪 |
| 一般步驟（L1、L2…） | 3 次 |

1. 到了上限就停，等使用者。
2. 同一個問題用同一種修法失敗 2 次，那種修法對那個問題禁用，要換做法。
3. 通過的物件凍結：只有組裝類的檢查點（L6、L9、L10、L11、L12）點名才能重開；手動 `wf redo objects/<名字>` 要寫原因。
4. 時限：整張立繪預估 120 分鐘，用掉兩倍就停。

## 6. 怎麼跑

```
python Tools/wf run <角色>/<造型>          跑到下一個要審查的地方（結束代碼 10＝等審查，20＝被擋住）
python Tools/wf review <角色>/<造型>       印出目前的審查包
python Tools/wf verdict <角色>/<造型> <審查包> <verdict.json> [--no-run]
python Tools/wf status [<角色>/<造型>]     每一步、每個物件的狀態和重做次數
python Tools/wf redo <角色>/<造型> <步驟 | objects/<物件>> --reason ...
python Tools/wf unblock <角色>/<造型> <步驟 | objects/<物件> | run> --reason ... [--more N]   （使用者）
```

- 工作資料夾：`art_work/live/<角色>/<造型>/`（主設計的造型是 `-`）。立繪來源：`<plates>/<角色>[/skins/<造型>]/`（`live2d.toml`）。
- **重跑一張已經做過的**：把舊資料夾**改名**留著（例 `-_wf1_20261002`），另開一個只放兩張立繪的新資料夾；不刪東西。
- **顯示卡是共用的**：用之前看 ComfyUI 的排隊（`/queue`），跟美術工具箱說一聲；跑完大工作看一次溫度。
- 流程程式的細節：[../Code/10_Workflow.md](../Code/10_Workflow.md)；設計：[../Design/23_Workflow.md](../Design/23_Workflow.md)。

## 7. 自動提醒（只是提醒，不是結論）

| 提醒 | 在哪一步 | 抓得到 | 抓不到 |
|---|---|---|---|
| 角色相似度（`char_score`，[22d](../Design/22d_Character_Score.md)） | L6（臉、頭髮、衣服三包）、L10、L11 | 整個換人、頭髮換色、臉換掉 | 小地方壞掉（一隻手臂換掉、關節段差、破洞） |
| 輪廓檢查（`outline --check`） | L5c | 物件不是一整塊、輪廓外有東西、沒上色的地方 | 形狀對不對 |
| 跟原圖比（`rig_check`） | L10 | 大塊缺少 | — 只當參考（原則 2） |
| 極限測試（`rig_stress`） | L12 | 背景透出來的洞、殘影 | 關節段差、凸塊（2026-10-02 手肘的例子） |

關節、接縫、物件邊緣一定要放大看（原圖解析度，裁到那裡放大 3～4 倍）。

## 9. 改流程的規則

- `flows/plate.toml`、這份總覽、步驟文件三者一起改；檢查點的編號三處一致。
- 各檢查點的「注意重點」寫在步驟文件的「注意重點」段（`**L<編號> 名稱**` 後面的條列），流程程式每次出審查包時從這裡讀（`plate.toml` 的 `focus = ["flow#L4"]`）。
- 新的心得寫進 [../LessonsLearned.md](../LessonsLearned.md)（現象 → 原因 → 解法），再在對應步驟的注意重點加一條、標出處。
- 例子只是說明過去怎麼出錯，不是規則；碰到不一樣的情況照原因判斷。
