# 14. 交付（L14，使用者確認）

回到 [主流程](README.md)。

## 做什麼、為什麼

整張做完，把結果交給使用者看、由使用者確認。

## 交什麼（照這個順序）

1. 物件檢查圖：`st/groups/parts_1.jpg`～`parts_6.jpg`。
2. 組裝圖：`st/groups/assemble_6.jpg`。
3. 動作：
   - 標準動作的總表。
   - 會動的圖（GIF）：揮手、跳躍、走路至少三個。
   - 四肢單獨疊起來、關節轉各角度的圖。
4. `llm_checks.md` 和 `run.json` 的 `manual`：通過了什麼、還沒解決的問題、手改清單（要做成工具的）。
5. `wf status`：每個物件重做幾次。

使用者不在電腦前時，用傳檔案的方式把圖送到手機。

## 看什麼

### 注意重點

**L14 交付**
- 先附物件檢查圖，再附組裝圖，最後附動作（原則 1）。
- 列出 `llm_checks.md` 裡沒解決的問題。
- `run.json` 的 manual 是選單外的手動修法：列成「要做成工具」的清單。
- `wf status` 看每個物件重做幾次。
- 用過大量顯示卡的話，交付時看一次溫度（LessonsLearned 二）。
- 結論由**使用者親口確認**（`by: "user"`）。

## 交付之後

- 使用者看出的問題（破圖、關節）：用 `wf redo objects/<物件> --reason "<使用者的話>"` 重開，後面的步驟會重跑。
- 新的心得寫進 LessonsLearned 和對應步驟的注意重點。
