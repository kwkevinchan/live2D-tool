# 經驗教訓

2026-09-29～10-02 在 towerD 和這個專案做這套工具時學到的事。

**怎麼寫**（使用者 2026-10-02）：每條記「現象 → 原因 → 解法」，寫成一般的規律，不寫成「某個角色在某種情況下要怎麼做」。具體事件只在「例」裡留一句，幫助理解，**不是規則**：碰到的情況不一樣時，照原因去判斷，不要照例子套。數字（像素、強度）是當時試出來的起點，不是標準。

跟流程有關的條目也整理進 `Docs/Design/22b_Live2D_Flow.md` 的「各檢查點的注意重點」，LLM 在每個檢查點照那份清單看圖。新增教訓時兩邊都要加。

## 一、原則（使用者定的，最重要）

對應的 LLM 檢查點：全部。

0. **物件要看得出來是物件**（最重要的前提）：每個物件單獨看，要一眼認得出是什麼。看不出來的，其他條件再好都不算通過；下面每一條都建立在這個前提上。
1. **驗收先看每個物件**：先看物件檢查圖（每個物件單獨一格），再看組裝圖和動作。原因：組起來時物件互相遮住，物件本身的缺塊、碎片、白洞會被蓋掉。每個物件要完整、乾淨、符合名字。交給使用者時也先附物件檢查圖。
2. **原圖只是素材，組起來像原圖不是目標**。原因：拆層的錯誤常常就藏在「看起來跟原圖一樣」的地方；為了對回原圖去補，會把錯誤一起帶回來。不要寫「貼回原圖像素」「切到原圖輪廓」這類規則，也不要拿「跟原圖並排很像」當成果。
3. **驗證的優先順序**：物件完整 → 一包組起來 → 整體組起來 → 動作。
4. **人物、武器、物件分開驗收**，各自通過才整合。原因：一起驗時，分不出破綻是誰造成的。
5. **先輪廓、後顏色**：輪廓決定形狀，輪廓外的就是雜點、輪廓裡沒顏色的就是要補的，判斷才明確。
6. **被擋住的也要畫完整**：大動作會露出原本被擋住的地方。左右成對的少一邊，從另一邊補。
7. **會分開動的就是不同物件**：四肢至少分上臂、前臂、手，大腿、小腿、腳掌（連鞋）；會自己擺的（髮束、披風、裙片）、穿過人物前後的（帽子、圍巾）也要拆開。
8. **判斷由 Claude 看圖做**，一格一格看；重做有上限（22b「三層檢查與重做上限」），到了上限才請使用者動手。

## 二、工作方式

- **每一輪修改開一個分支**，合併前整條分支審核；每次提交前確認目前分支。原因：多個對話共用資料夾時，分支可能被別人切走，提交會跑錯地方。
- **測試獨立一步跑**，看完結果才提交、合併、推送。原因：`跑測試 | grep … && 提交` 這種寫法，管線的結束狀態是 grep 的，測試失敗也會繼續往下做。
- **時限規則**：有風險的工作先估時間，超過兩倍就停下來，改用替代做法。研究類工作上限約 6 小時。
- **說時間之前先看時鐘**（`date`）。原因：憑做了多少事去猜，常常差很多。
- **下載超過約 5 GB 先問**（流量有限），要附上大小；也要注意第一次執行時會自動下載的工具。
- **共用顯示卡**：長時間的工作前先看 ComfyUI 佇列，不要在別人有工作排隊時重啟它；要吃滿顯示卡的（MV-Adapter）先請別人騰出來。大工作做完看一次溫度，不用一直記錄。
- **開視窗跑 Godot 時加 `--audio-driver Dummy`**，免得遊戲音樂吵到使用者。
- **權限被拒絕時，不要繞路**，停下來問使用者。原因：繞路的指令曾經丟掉未提交的修改。
- **使用者只讀中文**：回覆不夾英文術語（檔名、程式碼除外）。

## 三、拆層模型（See-through）

對應的 LLM 檢查點：L2、L4。

- **被擋住的部分常常畫錯**（顏色變灰、抄到旁邊東西的顏色、只留殘影）。
  - 原因：一個圖層只有在它是最前面的地方，才知道真正的顏色；被擋住的地方是模型猜的。
  - 解法：L2 時先記下，留到物件迴圈修（平塗、取旁邊的顏色、照輪廓重畫、參考多角度圖）。
  - 例：被瀏海擋住的額頭變灰，帽帶的顏色抄進臉裡。
- **該有的層沒有，或多出不存在的層**（漏掉臉、兩眼合成一層、發明帽子或翅膀）。
  - 原因：模型只會固定的二十幾個類別，每次拆的結果隨種子變。
  - 解法：補做（`object_fix --make-face`、`--split-lr`）、刪掉（`--drop-part`），整張拆壞就換種子重拆。
- **叫不出名字的東西被丟進「其他」**（長髮、寬帽、杖、長裙襬）。
  - 原因：模型的類別裡沒有它們（頭髮只有前髮、後髮兩類）。
  - 解法：依顏色、形狀、位置再分（`refine_leftover` 自動做一部分；長髮用 `--sort-hair`），分包時不能只看位置。
- **兩個東西顏色相同又疊在一起時，會被分在同一層**（頭髮疊在同色披風上，髮尾被分給披風）。
  - 原因：模型靠顏色和形狀分，同色的交界分不清。
  - 解法：用原圖的線稿和陰影判斷交界（`--move-hair`）。
- **兩個東西碰在一起時會黏成一塊**（手放在東西上）。
  - 原因：同上，交界不清楚。
  - 解法：從會動的那一個切出來，各自掛在該掛的地方。不處理的話，動作時另一個東西會跟著飛。
- 原始輸出存在 `st_layers.json`，`see_through.py --rebuild` 不用顯示卡就能重排（改了後面的規則想重來時用；會覆蓋所有修補）。

## 四、姿勢偵測（DWPose）與切武器（SAM2）

對應的 LLM 檢查點：L1、L3、L11。

- **關節抓錯或抓不到**。
  - 原因：姿勢偵測是用一般人體訓練的，盔甲、寬袖、外套、被東西擋住時會猜錯。
  - 解法：L1 看疊在立繪上的關節點，錯的手動改 `fig_joints.json`（原本的另存一份）。在這一步修最便宜：關節錯了，後面切零件、綁定都會跟著錯，零件會接不起來。
- **握點抓錯**。
  - 原因：自動判斷用「碰到武器最多的手」，手只是放在旁邊的東西上時也會被算進去。
  - 解法：看圖確認握點，錯了改 `parts.json` 的 `grip`。
- **SAM2 切武器時，負點不能是零個**，不然會出錯（`--not` 至少給一個不是武器的點）。

## 五、修補

對應的 LLM 檢查點：L3、L5a、L5b、L5c。

- **把前面擋住的東西的邊線，當成這個物件的邊**。
  - 原因：被擋住的地方，原圖上的線是前面那個東西的。
  - 解法：接線前，先跟另一邊（成對的、對稱的）比；只用物件邊緣往內一點的線。
  - 例：裙子前片的邊被當成小腿的邊，整塊被塗黑。
- **AI 照著底色畫**（補的地方留灰）。
  - 原因：從純色底重畫時，模型把底色當成要保留的內容。
  - 解法：先把缺口填上旁邊最近的顏色，再用中等強度重畫。
- **AI 把邊緣的雜色擴散開**（殘邊變成一圈色邊）。
  - 原因：重畫會延續輸入裡已有的顏色。
  - 解法：雜色先刪掉，不要畫在上面。
- **「取最近的顏色」拉出條紋**。
  - 原因：每個像素各自取最近的點，邊界附近會被拉長。
  - 解法：大片單色區域限定只用幾種顏色（`--palette`）。
- **切出來的零件邊緣有縫**。
  - 原因：從一層挖走一塊，下面就空了，零件一動就露出來。
  - 解法：會擺動的零件用「複製一份疊上去」（`--carve-copy`），下面那層保持完整，擺動在邊緣歸零。
- **鏡像過來的零件變粗**。
  - 原因：照兩邊骨頭長度的比例整個縮放，寬度也跟著變。
  - 解法：只沿骨頭方向拉長。
- **會動的零件上的小碎點跟著飛**：分離的碎點清掉（`--drop-specks`）。
- 判斷「哪些像素是猜的」可以參考跟原圖不一樣、被前面的層擋住，但**不要拿像不像原圖當歸屬或品質的標準**（原則 2）。

## 六、AI 重畫（Mage-Flow-Edit-Turbo、Qwen-Image-Edit-2511）

對應的 LLM 檢查點：L5b、L5c。

- **AI 畫的物件放回去擋到別的東西**（帽簷比原圖低、蓋住眼睛）。
  - 原因：AI 畫的物件形狀、角度跟原圖不同；照原圖的框放，多出來的部分就會壓到別的物件。
  - 解法：物件本身正確、風格接近就好（使用者 2026-10-02：「風格類似就好，物件正確才是最重要的」），在組裝時調位置、大小：照它旁邊的東西（臉、眼睛）決定放哪裡，必要時小一點。不要為了像原圖改用原圖去切，那是往「像原圖」拉（原則 2）。
  - 例：芙蕾雅主設計的帽子縮小約 7%、放高，帽簷剛好在眼睛上方。
- **AI 畫的物件放不回原位**（變大、置中、往下偏）。
  - 原因：修圖模型會把物件畫成「一張完整的商品圖」；拿拆層弄碎的原物件當對位目標，對位會被碎片帶歪。
  - 解法：看圖量出物件在原圖上的框，直接放進去（`object_place --box`）；目標可靠時才用 `--fit`。
- **去背把物件本身的白色挖掉**（火球中心的白光變成洞、分開的小火焰被刪）。
  - 原因：去背模型（rembg）憑樣子判斷背景，純白、跟主體分開的東西看起來就像背景。
  - 解法：物件裡本來就有白色、或由幾塊分開的部分組成的，用「只去掉從邊緣連進來的白」（`--matte white`）；其他用 rembg。
- **AI 畫的後髮是從背後看的**（頭頂、髮旋、整片亮面）。
  - 原因：「畫出長長的後髮」最常見的圖就是背影。正面立繪的後髮其實是頭和身體後面那片頭髮朝前的內側。
  - 解法：不要叫它畫「後髮」，叫它把人擦掉、在人原本的位置畫上後面那片頭髮的暗色內側；保持原圖的構圖。
- **綁定時把 AI 畫的頭髮換回原圖的顏色**（帽子、臉被印進前髮，轉頭時跟著頭髮動）。
  - 原因：綁定程式為了不讓前髮蓋掉護目鏡，把前髮每個像素換成原圖同一點的顏色；AI 畫的前髮範圍跟原圖不同，蓋到的帽簷、臉就被印進去。
  - 解法：放置工具在 `parts.json` 把 AI 畫的層標成 `drawn`，綁定時這種層保留自己的顏色。
- **頭髮擺動小到看不出來**（甩頭時髮尾只動幾個像素）。
  - 原因：甩頭是網格轉面，錨點在畫面上幾乎沒動，擺感覺到的動作很小；參數值小，換算成位移只有幾像素。
  - 解法：頭髮類的擺動角度輸出放大（`inx_rig.HAIR_GAIN`，3 倍；整片後髮 1.5 倍，3 倍時跳躍會甩出去），用部件動作測試的頭髮包看。
- **AI 畫的頭髮從帽子上冒出來**、**下巴下面多一塊淡色殘影**。
  - 原因：AI 畫的是完整的頭髮（含被帽子蓋住的頭頂），也會在臉、脖子的位置畫出淡淡的填色。
  - 解法：帽簷高度以上、沒被帽子蓋住的頭髮刪掉；臉附近偏白、偏粉紅、不是頭髮顏色的像素刪掉。

- **不一定照指令做，而且會改到沒要求改的地方**（位置、角度、方向，甚至把人留下來、把臉畫進物件）。
  - 原因：修圖模型會照它的理解重畫整張，不是只改指令裡的東西。
  - 解法：指令用英文命令句，明講「保持位置、大小、角度」；每個物件跑三個以上的種子挑；彎的、細長的、靠近臉的東西特別要看。四肢這類形狀要精準的，優先用修補而不是重畫。
- **只給白底，被物件圍住的白色去不掉**。
  - 原因：模型不輸出透明度，「從邊框往內找白色」的去背找不到圍住的白色。
  - 解法：預設改用 rembg 去背（`object_edit.py`，2026-10-02），圍住的白色會去掉（弓弦內側）；但物件本身的白色也可能被挖掉，見上一條。
- **送工作時被加上不相干的設定**：`ART_LORA` 環境變數會讓送工作的程式自動加上繪圖模型用的角色微調，這個模型用了會壞。呼叫前要拿掉。
- **放回去對位會歪**。
  - 原因：用整體重疊比例找位置，細長的東西重疊很少，很容易差一點就對不上。
  - 解法：對位要能旋轉、左右翻轉（`--fit --wide`），之後確認握點、關節點有沒有對上。

## 七、多角度參考（MV-Adapter）

對應的 LLM 檢查點：L5b。

- **顯示卡記憶體不夠**：一次最多 4 個角度（768 像素）；不能把一部分放到 CPU（會壞掉）。要先請其他工作騰出顯示卡，並設 `HF_HUB_OFFLINE=1`。
- **每個角度都畫成正面**。
  - 原因：角色微調太強時，會蓋過角度的控制。
  - 解法：微調強度壓低（0.3 以下起試）。
- **身體背面、武器畫不好**。
  - 原因：從一張正面圖推背面，資訊本來就不夠；武器和身體一起畫時互相干擾。
  - 解法：只拿來參考被擋住的部分，不取代看得到的部分；武器分開跑。

## 八、綁定與動作

對應的 LLM 檢查點：L6、L6b、L9。

- **整體動作看起來沒事，一包一包動才看到破綻**（武器黏著裙子碎片、補畫層的洞、補畫層蓋住頭髮）。
  - 原因：整體動作時物件互相擋住：黏在武器上的黑裙子疊在黑裙子上看不出來，大腿底下的洞被大腿蓋住。
  - 解法：綁定後先跑部件動作測試（`motion_test ... pack=<包>`），只畫那一包加補畫層，每個參數轉到兩端看。
- **補畫層畫到不該畫的地方**：人物外面（武器、手上的東西後面）、頭髮該在的地方、或留下畫布的灰色和空洞。
  - 原因：切零件時「被會動的零件蓋住的地方」都補，不管那裡後面原本是什麼。
  - 解法：補畫層只留在身體、衣服的範圍內；人物外面的刪掉；後面該是頭髮的地方留空（讓完整的後髮露出來）；大腿底下這種被蓋住的空洞用旁邊衣服的顏色補。
- **長武器跟著手臂甩到奇怪的角度**（跑步時法杖甩成橫的）。
  - 原因：手臂每個關節轉一點，一公尺長的武器末端就移動很遠。
  - 解法：長武器（比人物一半高）綁定時讓握點反向轉一部分（`inx_rig.UPRIGHT`），手臂擺動時保持大致直立；技能用的「武器旋轉」參數不抵銷。

- **擺動沒有跟著身體動**。
  - 原因：播放器的擺看的是錨點在世界中的位置，錨點掛在不會動的節點下就感覺不到動作。
  - 解法：擺要掛在會帶動它的節點底下（裙子掛在腿上、髮束掛在頭上）。
- **前後順序算錯**。
  - 原因：前後順序是沿著父節點加總的。
  - 解法：掛在別的節點下的零件，要換算回整體的順序再比。
- **左右兩邊動的方向相反**。
  - 原因：左右兩邊的參數各自定義，正負號不一致。
  - 解法：成對的關節統一「+ 是往外」。
- **腿交叉、腿踢出裙子外**。
  - 原因：動作的幅度沒有考慮站姿寬窄和衣服的範圍。
  - 解法：站得窄的，腿的側擺要小；長裙裡的腿，關節範圍要縮小，裙子跟著腿轉。
- **頭髮蓋在衣服後面、衣服蓋在頭髮前面這類順序錯誤**。
  - 原因：自動決定的前後順序不知道實際上誰在前。
  - 解法：照拆層的前後順序（`parts.json`）排，自動規則只用在拆層沒資訊的地方。
- 擺動的幅度、連動的比例都在 `inx_rig.py` 開頭的常數表（`SWING`、`SLEEVE_FOLLOW`……），是起點，看動作再調。

## 九、Godot

對應的 LLM 檢查點：L9。

- **無視窗模式畫不出東西**：要截圖的驗證要開視窗。
- **模型一格更新兩次**（物理跑兩倍快）。
  - 原因：Godot 在節點進場時會打開它的每格更新，先關再加進場景就白關了。
  - 解法：`set_process(false)` 要在 `add_child` **之後**呼叫。
- **語法錯誤讓測試卡住，而不是失敗**：從不定型別取值時寫明型別；自己的函式不要跟內建的撞名（例如 `_set`）。
- 「Unicode parsing error … NUL character」的警告是無害的雜訊。

## 十、Python、指令列、Windows

- **長的修改腳本塞進指令會壞掉**。
  - 原因：殼層會吃掉或改掉引號、反斜線、`\n`。
  - 解法：寫成檔案再執行；含 Windows 路徑的字串用原始字串。
- **解析「檔案:選項」把磁碟代號當成分隔符**：要從右邊切。
- **中文輸出亂碼或出錯**：Windows 主控台是 cp950，設 `PYTHONIOENCODING=utf-8`；讀檔指定 `encoding="utf-8"`。
- **輸出接 `| head` 出現 OSError**：管線提早關掉了，檔案其實已經寫出，先確認再說。
- **指令列太長（WinError 206）**：很多參數改成從檔案讀（`@檔案`）。
- **工具要用裝了 numpy、scipy、Pillow、opencv、rembg、gradio 的 Python**：這台電腦 PATH 上的 `python` 已經有。改完程式先跑 `Tools/run_tests.sh`。
- **變數撞名**：不要跟函式或外層變數同名；numpy 的布林值不要用 `is False` 比較。

## 十一、檢查方式

對應的 LLM 檢查點：L8、L9。

- **縮圖、動圖看不出細微的問題**。
  - 原因：縮小後細節不見；讀圖時動圖只看得到第一格。
  - 解法：看原尺寸；動作看「最大動作截圖」（參數到最大、最小的那幾格）。
- **組裝圖會遮住物件層級的問題**：見原則 1。
- **程式的檢查只能確認參數齊不齊、數字有沒有超標**；破綻（東西跟著手飛、關節有縫、碎片在飛）要看畫面才找得到。程式的警告只是提醒，結論看圖。
