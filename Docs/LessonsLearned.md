# 經驗教訓

2026-09-29～10-02 在 towerD 做這套工具時學到的事，從工作記憶和對話整理而成。每條盡量寫出「發生了什麼」和「以後怎麼做」。

## 一、原則（使用者定的，最重要）

1. **驗收先看每個物件**：先看物件檢查圖（每個物件單獨一格），再看組裝圖和動作。每個物件要完整（沒有缺塊、被擋住的也畫好）、乾淨（沒有別的東西的碎片、殘影、白洞）、符合名字。交給使用者時也先附物件檢查圖。
   - 發生的事：芙蕾雅 AI 版組起來「很像原圖」，逐個物件看才發現帽子、披風黏著頭髮碎片、髮尾有白洞、側髮切成碎塊。
2. **原圖只是素材，組起來像原圖不是目標**。為了對回原圖去補，會把拆層的錯誤一起帶回來。不要寫「貼回原圖像素」「切到原圖輪廓」這類規則，也不要拿「跟原圖並排很像」當成果（程式裡往這個方向拉的地方，列在 `Docs/Design/Project_Split.md` 第 3 節）。
3. **驗證的優先順序**：物件完整 → 一包組起來 → 整體組起來 → 動作。
4. **人物、武器、物件分開驗收**，各自通過才整合。
5. **先輪廓、後顏色**：物件拆出來 → 抽輪廓 → 補齊線條、刪輪廓外雜點 → 照輪廓補色 → 檢查完整度。
6. **被擋住的也要畫完整**，不然大動作會露破綻。左右成對的少一邊，就從另一邊補。
7. **四肢零件不能省**：手臂分上臂、前臂、手，腿分大腿、小腿、腳掌（連鞋）。
8. **穿過人物的物件拆成前後兩層**（帽子：帽冠、帽帶在瀏海前，帽簷在頭後）。
9. **判斷由 Claude 自己看圖做**（每一步的檢查點見 `Docs/Design/22b_Live2D_Flow.md`「LLM 檢查點」），畫面上的破綻要一格一格看；試兩三次還不行，才請使用者動手。

## 二、工作方式

- **每一輪修改開一個分支**，合併前整條分支審核。每次提交前確認目前分支（曾經因為別的對話切換了主資料夾的分支，提交跑錯地方）。
- **測試獨立一步跑**，看完結果才提交、合併、推送。不要寫成 `跑測試 | grep … && 提交`：管線的結束狀態是 grep 的，測試失敗也會繼續（曾經因此推送了有失敗測試的版本）。
- **時限規則**：有風險的工作先估時間，超過兩倍就停下來，改用替代做法。研究類工作上限約 6 小時。
- **說時間之前先看時鐘**（`date`），不要憑做了多少事去猜。
- **下載超過約 5 GB 先問**（流量有限），要附上大小；也要注意第一次執行時會自動下載的工具。
- **大型顯示卡工作做完後，看一次溫度**就好，不用一直記錄。
- **跟其他對話共用顯示卡**：長時間的工作前先通知、先看 ComfyUI 佇列；不要在別人有工作排隊時重啟 ComfyUI。MV-Adapter 這種要吃滿顯示卡的，要請對方先騰出來。
- **開視窗跑 Godot 時加 `--audio-driver Dummy`**，免得遊戲音樂吵到使用者。
- **權限被拒絕時，不要繞路**：曾經用 `git checkout --` 丟掉了未提交的修改，之後要讀備份又被拒。被拒就停下來，問使用者。
- **使用者只讀中文**：回覆不夾英文術語（檔名、程式碼除外）。

## 三、拆層模型（See-through）

- 一個圖層只在「它在最前面」的地方有原圖顏色；被擋住的部分是它猜的，**常常猜錯**：
  - 被瀏海、帽子擋住的額頭填成灰色。
  - 把帽帶的黑、紅抄進臉裡（帽子那層反而空了一塊）。
  - 頭後面的帽簷沒補，只留灰色殘影。
  - 後髮大半補成灰白色。
- **有時漏掉臉、兩隻眼白合成一層（甚至只有一隻）、發明不存在的帽子**（芙蕾雅服裝 C）。用 `object_fix --make-face`、`--split-lr`（缺的那隻從另一隻鏡像）、`--drop-part`。
- 只認得前髮、後髮兩種頭髮：**披到肩上的長髮會被丟進雜物層 `leftover`**；分包如果只看位置，長髮就會跑到「其他」、綁在腰上。用 `--sort-hair` 依顏色分出來。
- **頭髮跟同色的披風疊在一起時，髮尾會被分給衣服**（`--move-hair`，用原圖線稿和頭髮的灰藍陰影判斷）。
- **手放在東西上時會黏成一塊**（艾莉西亞的右手和箭筒），跑步時箭筒跟著手飛。要從手切出來，掛在身體上。
- 原始輸出存在 `st_layers.json`，`see_through.py --rebuild` 可以不用顯示卡重新排回去（改了切零件的規則想重來時用）。

## 四、姿勢偵測（DWPose）與切武器（SAM2）

- **盔甲會讓姿勢偵測抓錯手腕**（芙蕾雅服裝 C：右手腕沒找到、左手肘手腕放在肩膀上）。看格線圖讀出正確座標，手動改 `fig_joints.json`，原本的另存一份。
- **握點常抓錯**：自動找的是「碰到武器最多的手」，會抓到放在箭筒上的那隻手，或劍柄上方。看圖改 `parts.json` 的 `grip`。
- 姿勢偵測原本只存髖，沒存膝蓋、腳踝，主設計和服裝因此切不出腿（已修：也存膝蓋、腳踝）。
- **SAM2 節點至少要一個「不是武器」的點**，不然會出錯（`--not`）。

## 五、修補

- **擋在前面的東西的邊線，不是這個零件的邊**：曾經把裙子前片的邊當成小腿的邊連起來，結果整塊被塗黑。接線之前先跟另一邊比。
- **從灰底直接重畫，AI 常照著背景留灰**：先把缺口填上旁邊最近的顏色，再用強度 0.8 重畫。
- **邊緣的頭髮殘邊，交給 AI 會擴散成一圈紅邊**：殘邊直接刪（`--erase-rgb`），不要畫在上面。
- **「取最近的顏色」會拉出條紋**：大片單色區域限定只用幾種顏色（`--palette`）。
- **用方框切出的零件（胸）會在邊緣留縫**：改成「複製一份疊上去」（`--carve-copy`），下面那層保持完整，擺動在邊緣歸零。
- **鏡像時只沿骨頭方向拉長**，不然整隻手臂會跟著變粗。
- **骨架點錯了，零件會接不起來**：右手腕點高了 50 像素，前臂碰不到手。
- **移動的零件上的小碎點會跟著飛**：`--drop-specks`。
- **把整層切空之後，綁定程式會出錯**（已修：空圖層跳過）。
- 判斷「哪些像素是猜的」可以參考跟原圖不一樣、被前面的層擋住，但**不要拿跟原圖像不像當成歸屬或品質的標準**（見原則 2）。

## 六、AI 重畫（Mage-Flow-Edit-Turbo）

- 指令用**英文命令句**最穩，要明講「保持位置、大小、角度」。
- 構圖大致會保留，但**不是逐像素保留**，沒要求改的地方也會被重畫一點。
- 只會給**白底**，不會給透明背景；**被物件圍住的白色去不掉**（弓弦內側、髮捲之間）。
- 同一套指令**大約一半照做**，偶爾完全不理（人還在、把臉畫進頭髮裡）：每個物件跑三張挑一張。
- **會改姿勢角度**：手臂被拉直、弓弧方向畫反。寫「do not straighten or move」有時有用。
- **擅長**：頭髮、披風、帽子、直的武器。**不擅長**：四肢、彎的武器、容易被畫進臉的東西。
- 呼叫前要拿掉 `ART_LORA` 環境變數，不然送工作的程式會自動加上 SDXL 的角色微調，圖會壞。
- 放回去對位時要能旋轉、左右翻轉（`--fit --wide`）；用整體重疊對位，細長的物件（法杖、手臂）容易歪，要看握點、骨架點有沒有對上。
- 曾經用「後面的層露出來的地方要留空」修好裙子蓋住腿的問題；但「看得到用原圖」整條規則本身是錯的方向（原則 2）。

## 七、多角度參考（MV-Adapter）

- 一次最多 4 個角度（正、右、背、左，768 像素）；6 個會爆 16 GB。
- 角色微調強度不能超過 0.3，否則每個角度都畫成正面。不能用 CPU 分擔（會壞掉）。
- 武器要跟身體分開跑；身體的背面常畫不好（芙蕾雅背後是一塊粉紅色）。
- 只拿來參考被擋住的部分（後髮、帽子後半），不要拿來取代看得到的部分。
- 在 ComfyUI 外面跑，要先請其他人騰出顯示卡；要設 `HF_HUB_OFFLINE=1`。

## 八、綁定與動作

- **物理擺動看的是錨點的世界座標**：擺掛在會轉的節點下面才會被帶動（裙子的擺掛在膝蓋上，走路時才會慢半拍甩）。
- **前後順序（zsort）是沿著父節點加總的**：頭節點在 -0.5，掛在頭上的零件要算回絕對值。
- **手臂、腿的參數方向要左右一致**（+ 都是往外）：曾經左右相反，揮手時手臂往胸前收。
- **站得窄的角色，腿會交叉**：標準動作的腿側擺要小、膝蓋往外彎。
- **長裙過膝時，髖、膝的範圍要縮小**，不然腿會踢出裙子外；裙子要跟著腿轉。
- 披風要排在髮尾後面（頭髮蓋在披風上）；側髮在上衣前、手臂後。
- 擺動的幅度、連動的比例都在 `inx_rig.py` 開頭的常數表（`SWING`、`SLEEVE_FOLLOW`…）。

## 九、Godot

- **無視窗模式畫不出東西**，要截圖的驗證要開視窗。
- `set_process(false)` 要在 `add_child` **之後**呼叫，不然 Godot 進場時會打開，模型一格更新兩次、頭髮物理跑兩倍。
- GDScript 語法錯誤會讓測試卡住而不是失敗；從 Variant 取值要寫明型別（`var x: float = ...`）。
- 自己的函式不要叫 `_set`（跟 Object 內建的撞名）。
- 「Unicode parsing error … NUL character」的警告是無害的雜訊。

## 十、Python、指令列、Windows

- **長的 Python 修改腳本不要用 heredoc 直接塞進指令**：引號、`\n` 會被殼層吃掉或弄亂。寫成檔案再執行。
- **路徑的磁碟代號 `C:` 會被當成分隔符**：解析 `檔案:選項` 這類參數時要從右邊切。
- **Windows 主控台是 cp950**：中文輸出要設 `PYTHONIOENCODING=utf-8` 或 `-X utf8`；讀 JSON 要指定 `encoding="utf-8"`。
- **輸出接 `| head` 會在程式還在寫時關掉管線**，產生 OSError；檔案其實已經寫出，看到錯誤先確認。
- **Windows 指令列長度有限**（WinError 206）：很多參數改成從檔案讀（`@檔案`）。
- `Tools/fetch.py` 會把整個檔案讀進記憶體再寫出，同時下載幾個大檔要注意記憶體。
- 需要 OpenCV 的工具要用有裝的 Python 環境（towerD 的 `myenv`）。
- 變數不要跟函式或外層變數撞名（`label`、`out` 都曾經出錯）；numpy 的布林值不要用 `is False` 比較。

## 十一、檢查方式

- **縮圖看不出細微的動作問題**（胸部彈動、領口跟轉頭）：只能確認沒有破綻，好不好看要在實際大小、實際速度下看。
- **靜態組裝會遮住物件層級的問題**：見原則 1。
- **程式的檢查只能確認參數齊不齊**；破綻（箭筒跟著手飛、手腕有縫、碎片在飛）要看畫面才找得到。
